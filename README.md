# SiliconMacOSOS

SiliconMacOSOS is a native operating-system project for Apple Silicon Macs,
with first-class instructions for the M5 MacBook Air.

> [!IMPORTANT]
> The M5 family may not be supported by an operating system or installer yet.
> Apple changes the boot chain, GPU, storage, USB, and firmware interfaces
> for each platform generation. Before changing your Mac, verify that your exact
> M5 model is listed by the installer and distribution you intend to use.
>
> This guide does **not** use virtualization: the alternate OS is installed
> directly on the Mac and selected from macOS Startup Options.

## Recommended path: Asahi Linux

Asahi Linux is the maintained, end-user-friendly base for running Linux natively
on supported Apple Silicon Macs. It provides:

- direct booting from the Mac, not a VM
- an ARM64 Linux environment
- macOS and Linux dual-boot support
- the `m1n1` and Asahi firmware integration needed by Apple Silicon

The current recommended distribution must be selected in the official installer.
Do not install a generic x86_64 or UEFI Linux image on an Apple Silicon Mac.

Official resources:

- [Asahi Linux](https://asahilinux.org/)
- [Asahi Linux documentation](https://asahilinux.org/docs/)
- [Open OS interop and boot process](https://asahilinux.org/docs/platform/open-os-interop/)
- [Apple: changing the startup disk](https://support.apple.com/HT202796)

## Before installation

You need:

- the M5 MacBook Air
- macOS with FileVault unlocked
- a full Time Machine or disk-image backup
- a wired or reliable Wi-Fi network
- at least 80 GB of free storage for a desktop Linux installation
- 2–4 GB of free storage for the recovery/boot partition
- administrator access to macOS
- the password for the macOS account

Back up the Mac, then check the storage layout in **Disk Utility**. An operating
system cannot share the complete macOS APFS container; the installer creates
or assigns separate storage for Linux.

## Check M5 support

Open **Terminal** in macOS and run:

```sh
sw_vers
system_profiler SPHardwareDataType
```

Record the exact model identifier and macOS version. Cross-check both with the
latest Asahi Linux hardware support page or run the installer, which detects
whether it supports the hardware.

If M5 support is absent, stop here. Do not bypass the support check or install
a generic ARM64 Linux image without a hardware-specific boot and device
configuration: it may be unbootable and may leave peripherals or graphics
unsupported.

## Install Asahi Linux natively

This procedure creates native M1, M2, M3, M4, or future-generation support
where it exists. It does not claim M5 support that the Asahi project does not
yet provide.

1. Keep the Mac connected to power.
2. Open **Terminal** and enter:

   ```sh
   curl -L https://alx.sh | sh
   ```

3. Read every installer prompt. The installer will check macOS and hardware
   compatibility, install the helper partition and `m1n1`, and offer a
   download of a supported Linux distribution.
4. Choose enough disk space for the Linux partition.
5. Let the installer finish and reboot when it requests it.
6. On first boot, approve the OS-reduction or reduced-security prompt if it is
   shown. Use only the exact prompt generated by the installer; never enter
   arbitrary commands from a forum post.
7. Follow the distribution's first-boot setup to create the Linux user.

If macOS blocks the downloaded installer, use **System Settings → Privacy &
Security** and allow the action only if you verified the URL and prompt.

## Starting macOS or Linux

For an M5 Mac, shut down completely, then hold the **power button** to open
Startup Options. Select macOS or the Asahi Linux volume.

To keep macOS as the current/default volume:

1. Boot into macOS.
2. Open **System Settings → General → Startup Disk**.
3. Select the macOS volume.

For a later Apple boot menu layout, use **Apple Menu → Restart**, hold the
power button while it restarts, select the desired volume, and then authenticate
if requested.

## Updating

Update macOS and Linux independently.

In macOS:

- install macOS updates through **System Settings**
- keep a macOS recovery path available
- do not reinstall Linux unless the project's upgrade instructions require it

In Linux:

```sh
sudo dnf upgrade
```

For Fedora-based Asahi installations, use `dnf`; for another distribution,
use that distribution's official package manager:

```sh
sudo apt update && sudo apt full-upgrade
```

After firmware or kernel updates, reboot and confirm the Linux kernel and
graphics/network devices before assuming the update is complete.

## Removing Asahi Linux

Only remove a Linux installation with the official Asahi tooling. The generic
macOS Disk Utility erase operation does not necessarily remove `m1n1`, the
recovery partition, or all OS metadata.

Boot macOS and run:

```sh
curl -L https://alx.sh | sh
```

Choose the installer option that removes Asahi Linux or restores the macOS-only
disk layout. Confirm the action in macOS Disk Utility afterward and make a
fresh Time Machine backup.

Apple recovery procedures remain the final fallback. Use macOS Recovery to
restore or reinstall macOS if the boot chain is damaged.

## Building another ARM64 operating system

Asahi Linux is an existing native OS, not a source-built OS shipped by this
repository. If SiliconMacOSOS is intended to become an independent distribution,
use the supported Asahi software and Linux distribution as the starting point
and keep the following platform layers separate:

1. **Boot chain:** Apple's boot policy, `m1n1`, and a chainloaded ARM64 loader.
2. **Kernel:** an ARM64 kernel with Apple M-family SoC support.
3. **Firmware:** only the firmware and helpers licensed or provided for Apple
   Silicon Macs.
4. **Drivers:** PCIe/DT/ACPI and platform-specific support for storage, GPU,
   Wi-Fi, Bluetooth, USB, keyboard, trackpad, camera, and audio.
5. **User environment:** an independent package set and init system.
6. **Installer:** signed, verified partitions and recovery media.

Do not copy x86 BIOS boot code, x86 UEFI firmware assumptions, or x86 package
repositories into this project. An ARM64 Linux root filesystem is only reusable
after device support has been added for the exact SoC and the boot chain is
compatible.

At minimum, an M5 port must demonstrate, on physical M5 hardware:

- secure boot-chain recovery
- macOS dual-boot and macOS Recovery
- NVMe storage
- USB and Thunderbolt
- Wi-Fi and Bluetooth
- display output and accelerated graphics
- keyboard and trackpad
- camera and audio
- suspend/resume and battery/power management
- thermal and fan behavior

## Repository scope

This repository currently provides installation and operating-system guidance.
It does not contain a prebuilt M5 kernel or disk image, and it does not claim
M5 support until that support is independently verified.
